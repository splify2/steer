# Список изменений steer

Раздел версии отсюда попадает в текст выпуска на GitHub и в
[splify2/releases](https://github.com/splify2/releases) (`release.yml`, шаг «Текст выпуска»).

## 2.1.0

🛠 **steer 2.1.0** — новый модуль WARP, выбор самых быстрых узлов, быстрее туннели и исправления DNS и маршрутизации 👇

### 🐞 ИСПРАВЛЕНИЯ
✅ Собственный трафик steer больше не проходит через общий zapret  
✅ Замеры членов групп (туннели и over) больше не теряются на локальном интерфейсе  
✅ Блокировка `block` действует только в исходном направлении трафика  
✅ Снятие правил удаляет только правила своей пары метки и таблицы  
✅ Проверка здоровья выхода по TCP идёт через его метку, а не через TUN  
✅ Туннели берут настоящий адрес fake-IP из ядра, а не только из файла  
✅ hysteria2 с режимом Brutal: лимит отправки делится между соединениями, а не применяется к каждому отдельно  
✅ Группы DNS-серверов в режиме race: при отказе серверов группа уходит на паузу, а поздний ответ больше не снимает отказ  
✅ Группа WARP при старте не делает ложной замены точки  
✅ xhttp packet-up: POST-запросы не превышают лимит узла `scMaxEachPostBytes`, размер каждого запроса случайный  
✅ `rm-file` работает и тогда, когда спека записана в YAML  
✅ TCP-стек: сегменты, пришедшие не по порядку, корректно ждут закрытия дыры  
✅ Пул адресов fake-IP больше не кончается на долгоживущем устройстве: адреса имён, которых давно не спрашивали и к которым нет соединений, возвращаются  

### 🔧 ИЗМЕНЕНО
▫️ Переход с 2.0.x: `steer-core` 2.1.0 при установке снимает пакеты `steer-vless`, `-hysteria2`, `-proxy`, `-xsteer`, `-obfs`, `-warpbox` и `steer-extended` (apk — `provides`/`replaces`, opkg — `Conflicts`), а `steer plugin migrate` ставит нужные плагины протоколов из семени без сети по видам выходов спеки; `kmod-tun` остаётся за ядром, `steer-tgws` обновляется вместе с ним (ставить `steer-core` и `steer-tgws` одной командой)  
▫️ Выход `kind: zapret` удалён вместе с обработчиком `steer-nfqws` и командой `zapret-instances`: спека с ним отвергается с названием замены — модуль DPI recheck или `kind: direct`; `on_fail: zapret` (уживание с системным zapret) остался  
▫️ Из ядра убраны остатки совместимости и код без вызовов: раскладка для Linux 4.9, чтение форматов времён до 2.0.0, неиспользуемые функции, макросы и поля  
▫️ TCP-трафик клиентов теперь идёт только через ядро steer, собственный TCP-стек туннеля удалён  
▫️ Группы с `order` и `latency` закрепляют соединение за выбранным узлом  
▫️ Туннели используют несколько рабочих потоков по числу ядер и раздают пакеты без замков — выше скорость на многоядерных роутерах  
▫️ Туннель отдаёт клиенту большие записи (до 64 КБ вместо 8–9 КБ) — меньше накладных расходов  
▫️ hysteria2: UDP отправляется и принимается пачками — примерно вдвое меньше нагрузки на процессор  
▫️ Допуск группы `warp` по умолчанию 50 мс (было 200 мс)  
▫️ fake-vless: очередь входящих соединений 512 (было 5)  
▫️ Выход `kind: block` в выводе отображается как «Блок»  
▫️ Раскладка набора правил для Linux 4.9 удалена: нужен nat в `inet` (Linux 5.2 и новее)  
▫️ Спека v1 читается и переводится в v2 при загрузке; её ответы на AAAA теперь те же, что у v2  
▫️ Режим `realip` остаётся полноценным: предупреждение о его уходе убрано  
▫️ Круг `steer failover --loop` убран: выходы сторожит демон с `--watch`  
▫️ Файл состояния fake-IP пишется в фоне через секунду после изменения, а не раз в минуту  
▫️ steerd собирается с `-O2`  

### ✨ НОВОЕ
✅ `steer spec-schema [--json]` — схема всей спеки v2: ключи, типы, значения, умолчания, подсказки, ссылки на имена и ключи каждого вида выхода; виды установленных плагинов вливаются с пометкой плагина  
✅ Менеджер плагинов: `steer plugin` ставит, обновляет, снимает, включает и выключает плагины из подписанных репозиториев, без сети — из семени; те же действия — командами сокета `plugin-*`  
✅ Плагины обновляются в фоне: раз в сутки, установка в ночном окне, при неудаче проверки здоровья — откат на прежнюю версию  
✅ `steer version --json` называет версии ядра, steer-api и steer-abi  
✅ Модуль WARP (warpbox): регистрация, подбор точек и сторож туннелей  
✅ В спеке v2 появился вид `kind: warp` — группа WARP-туннелей  
✅ WARP по умолчанию — один туннель, который на ходу переходит на самую быструю точку  
✅ Без `countries` и `exclude_countries` WARP берёт точки любых стран  
✅ Члены WARP: быстрый отказ и транспорт MASQUE (`transport: masque`)  
✅ У членов WARP есть IPv6, по умолчанию через NAT  
✅ Пул подписки: режим `pick: latency` берёт самые быстрые узлы в одно устройство  
✅ Выбор узла по стране: `only` берёт узлы только указанных стран, вместе с `pick: latency` и `exclude` — «самый быстрый, кроме страны X»  
✅ Группы выходов: `only` и `exclude` по стране живого узла члена — «самый быстрый, кроме страны X»  
✅ Страна выхода туннеля: заявленная по имени узла и фактическая по проверке через выход, расхождение помечается  
✅ `pick: latency` оценивает узел и члена группы по трём пробам — задержка, разброс и потери  
✅ IPv6 у узлов: подключения TCP и UDP по IPv6, в ссылках и выводе адрес в квадратных скобках  
✅ DNS-over-HTTP/3: апстрим `h3://имя[:порт][/путь]` в резолвере  
✅ DoT и DoH: ClientHello можно делить на две записи TLS (ключ `fragment` у апстрима)  
✅ `steer dns-probe` проверяет DNS-серверы через апстримы резолвера  
✅ `steer spec convert --json` выводит спеку v2 JSON-объектом  
✅ `status` показывает состояние WARP-туннелей, а также колонию и страну живого туннеля  
✅ `status` показывает, поддерживаются ли деление ClientHello и DoH3
✅ Семейство IP по правилам: `family: 4 | 6 | both` и `on_family_unavailable: block | fallback` — IPv6 без утечек, управление по сервисам
✅ `dns.mesh_clients: true` заворачивает запросы DNS клиентов Tailscale и ZeroTier на резолвер steer — доменные правила действуют и на них (по умолчанию выключено)  
✅ xsteer: бит FLAG_SPLIT в рукопожатии — пачки кадров только пиру, который умеет их собирать; прежние клиенты и хабы работают как раньше  
✅ IPv6 через туннели (VLESS, hysteria2, прокси): TCP и UDP клиентов по IPv6 идут через выход, правила с `family: 6` и `both` ведут в него оба семейства; `ipv6: off` у выхода это отключает  

## 2.0.5

🛠 **steer 2.0.5** — исправления шифрования на big-endian MIPS, обрывов соединений и падения dnsd, прокси-ссылок и проверки https-адресов 👇

### 🐞 ИСПРАВЛЕНИЯ
✅ На роутерах с big-endian MIPS хеши и AES-GCM считались неверно (как на little-endian) — исправлено  
✅ Shadowsocks и VMess: при больших порциях расшифрованных данных соединение больше не обрывается  
✅ Проверка https:// теперь передаёт ALPN http/1.1, как обычный HTTP/1.1-клиент, — серверы, которые выбирают протокол по ALPN, отвечают ожидаемо  
✅ Список JSON без закрывающей скобки теперь даёт отказ с понятной ошибкой, а не тихо продолжает разбор с неверными данными  
✅ dnsd: при нехватке памяти при загрузке набора правил демон больше не падает  
✅ Набивка «0» или «0-0» теперь действительно отключает набивку, а не включает случайную от 100 до 1000 байт  
✅ Прокси-ссылки: пароль или конфиг vmess длиннее допустимого больше не обрезаются молча — выводится причина отказа  

### 🔧 ИЗМЕНЕНО
▫️ Ключи и секреты протоколов затираются из памяти надёжно — компилятор их больше не может оставить в памяти  
▫️ В документацию добавлено, что делать, если после прерванной установки apk пишет «breaks: world[…]»

## 2.0.4

🛠 **steer 2.0.4** — исправления по обращениям из чата splify2 и steer#6, ускорение туннелей 👇

### 🐞 ИСПРАВЛЕНИЯ
✅ VLESS: после нескольких проверок узла он больше не начинает молчать на ClientHello — одна проверка открывала к узлу до пяти соединений сразу, и сервер или провайдер начинал их резать. Запасные соединения теперь заводятся, только когда через выход действительно идёт поток, а после отказа узла пауза растёт с 5 до 60 секунд  
✅ VLESS Reality и TLS: если узел не ответил на длинный ClientHello (с постквантовым обменом ключами), ядро сразу пробует короткий и запоминает узел на час  
✅ Выход из смешанной подписки (vless + hysteria2): узел, который отвечает на проверку, но не держит соединения, считается мёртвым — выход переходит на другой протокол  
✅ Возврат на оживший узел — не дольше 30 секунд, а не через 5 минут  
✅ hysteria2: одна большая UDP-датаграмма больше не останавливает туннель целиком  
✅ UDP больше 4 КБ проходит через VLESS и hysteria2 (крупные ответы DNS, игры, звонки); фрагменты собираются в любом порядке, первая крупная датаграмма нового соединения не теряется  
✅ Выгрузка изредка стояла больше 10 секунд в начале соединения — исправлено  
✅ Подписки: значки в именах узлов (⚡ ⭐ 📱) больше не превращаются в «u26a1»; ссылки с `type=raw` больше не отбрасываются; узел с Vision поверх gRPC или xhttp пропускается с понятной причиной, а не перезапускает выход без конца  
✅ Пул узлов: при «работают сразу» больше 64 соединения раздаются на все узлы  
✅ Смена выхода у правила при очень больших списках больше не подвешивает ядро на секунды

### 🔧 ИЗМЕНЕНО
▫️ Выгрузка через gRPC и xhttp больше не упирается в окно узла (по замеру автора правки — в разы быстрее), а скачивание рядом с выгрузкой больше не проседает; xhttp packet-up — в несколько раз быстрее. Правки стека TUN и xhttp перенесены из [hoaxisr/tunvless](https://github.com/hoaxisr/tunvless) — спасибо hoaxisr  
▫️ xhttp: настройки по Xray 26.3 — выгрузка по второй связи снова работает  
▫️ Соединения, где первым говорит сервер (SSH, почта), больше не зависают через туннель

## 2.0.1

🛠 **steer 2.0.1** — исправления по итогам сравнительного замера и проверок 👇

### 🐞 ИСПРАВЛЕНИЯ
✅ hysteria2: выгрузка больше не замирает на скорости выше ~300 Мбит/с — раньше через пару секунд поток вставал в ноль  
✅ hysteria2: память модуля при быстром скачивании в несколько потоков — около 25 МБ вместо сотен; роутер больше не уходит в OOM  
✅ hysteria2: медленный получатель больше не ждёт по 10 секунд — окно приёма уходит серверу сразу  
✅ VLESS и другие туннели: модуль погибал при обрыве соединений на скорости (SIGPIPE), и туннель лежал 5–20 секунд до перезапуска  
✅ Если все узлы подписки исключены через «Не брать», статус говорит об этом прямо, а не «в подписке нет пригодных узлов»

### 🔧 ИЗМЕНЕНО
▫️ Выгрузка через туннели больше не упирается в 64 КБ на круг до клиента: окно TCP с масштабом (RFC 7323). При задержке до клиента 6 мс один поток — 1,4 Гбит/с вместо 83 Мбит/с  
▫️ У hysteria2 окно клиента ограничено 128 КБ, чтобы очередь к мультиплексору не переполнялась

## 2.0.0

🚀 **steer 2.0.0** — полный список изменений после 1.5.9 👇

⚠️ Ядру 2.0 нужен **splify2 26.10.0** или новее. Обновляйте так: сначала splify2, потом ядро — интерфейс сам поставит ядро и нужные модули. Правила, списки и подписки сохраняются.

### 🆕 НОВОЕ

🧩 **Ядро и протоколы — отдельными пакетами**  
▫️ `steer-core` — само ядро, протоколы ставятся модулями: VLESS, hysteria2, прокси, xsteer, обфускатор, мост Telegram  
▫️ Ставится только то, чем вы пользуетесь, — роутеру с маленькой памятью это заметно

⚡ **hysteria2 — новый протокол**  
▫️ Быстрый туннель поверх QUIC (UDP), BBR или Brutal, обфускация Salamander, прыжки по портам  
▫️ Работают узлы, у которых вместо имени указан IP-адрес (так раздают серверы на Xray 26.9)  
▫️ Соединение с узлом держится постоянно — без переподключений каждые пару минут

🌐 **Прокси из подписок**  
▫️ Trojan, Shadowsocks (и 2022), SOCKS, HTTP(S), VMess — из подписок и вставкой ссылки

🔢 **Несколько узлов сразу**  
▫️ Выход по подписке держит сразу N живых узлов, трафик делится между ними  
▫️ Три способа раздачи: каждое соединение на любой узел, сайт целиком на одном узле, сайт и устройство на одном узле  
▫️ Отказавший узел заменяется следующим без перезапуска туннеля

🩺 **Отвал узла виден сразу**  
▫️ Если узел замолчал посреди закачки, звонка или игры, ядро за ~20–30 секунд обрывает зависшие соединения — приложения сразу переподключаются через живой узел  
▫️ Период проверки и порог молчания настраиваются

🚫 **«Не брать» узлы**  
▫️ Исключение узлов подписки по стране и по словам в названии — переживает обновление подписки

⚖️ **Группы выходов**  
▫️ Первый живой, самый быстрый, выбор вручную, «поровну» — по соединению, сайт на одном выходе или сайт и устройство на одном выходе  
▫️ Группы можно вкладывать друг в друга

🔐 **Свой DNS**  
▫️ DoH, DoT, DoQ и обычный DNS, напрямую или через выход, с кэшем  
▫️ Свой сервер у каждого правила  
▫️ Несколько серверов сразу (кто ответит первым) или по очереди (при отказе — следующий)  
▫️ Отдельный сервер для сайтов вне правил; не ответил — запросы идут прежним путём, интернет не пропадает

🛡 **VLESS**  
▫️ Постквантовая защита Reality (ML-KEM) — узлы на свежем Xray-core снова подключаются  
▫️ VLESS encryption, ECH, транспорты ws и httpupgrade, UDP через Vision  
▫️ Закрепление сертификата узла и «не проверять сертификат» для узлов с allowInsecure

🌍 **IPv6** — правила, выходы и подмена адресов работают и по IPv6

📦 **Списки sing-box** (`.srs`), включая фильтры AdGuard

📶 **Новая архитектура** `aarch64_cortex-a72` — всего десять

### 🔧 ИЗМЕНЕНО
▫️ Настройки применяются без обрывов: ядро трогает только то, что изменилось  
▫️ Сменили правилу выход — его открытые соединения сразу переходят на новый выход (раньше доживали на старом, и сайты вроде YouTube видели два адреса)  
▫️ Снятые снаружи правила и маршруты ядро возвращает само  
▫️ `steer-extended` теперь нужен только для перехода с 1.x — новым установкам он не нужен  
▫️ Шифрование — wolfSSL вместо mbedtls  
▫️ Прежние настройки 1.x читаются как есть

### 🐞 ИСПРАВЛЕНИЯ
✅ Узлы Reality на Xray 26.9.8+ снова работают (раньше — «узел не признал ключ»)  
✅ hysteria2 с IP-адресом вместо имени подключается (раньше — «QUIC не открылся»)  
✅ Диагностика замечает выключенное устройство выхода  
✅ Имена правил кириллицей в журнале имён — без «кракозябр»  
✅ Переход с 1.5.9 через opkg больше не удаляет ip-full, conntrack и kmod-tun  
✅ Датаграммы UDP в начале соединения hysteria2 больше не склеиваются

### 🗑 УБРАНО
▪️ Единый пакет `steer` — вместо него `steer-core` и модули
