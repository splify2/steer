# Cloudflare WARP (плагин warpbox)

Плагин `warpbox` — выход через Cloudflare WARP одной строкой спеки. Он регистрирует устройства
WARP, подбирает рабочие точки входа, следит за ними и меняет ту, что перестала отвечать. Вид `warp`
объявляет его манифест: без плагина выход `kind: warp` недоступен («нужен плагин warpbox»). В телефонную
сборку плагин не входит.

```yaml
outputs:
  cf: { kind: warp }
rules:
  - { to: [blocked], out: cf }
```

## Как устроено

`kind: warp` — это группа (`pick: latency`) из `count` туннелей `cf.1`, `cf.2`, … вида `awg` (у `transport: masque` — устройства TUN плагина). По
умолчанию туннель один (`cf.1`): самую быструю точку входа плагин держит у этого же устройства сам
(ниже, «Самая быстрая точка»). Устройства,
метки, таблицы, здоровье и выбор живого члена у них те же, что у любого выхода `awg` и любой группы
ядра steer: плагин не заводит ни интерфейсов netifd, ни зон и правил фаервола. Группу из выхода
`kind: warp` разворачивает хук `expand` плагина (`warp-expand`, `src/proto/warp/wbexpand.c`) при подготовке
спеки, а ядро только применяет развёрнутое; помощник группы — программа плагина: ядро поднимает её само и
даёт ей {conf} группы с членами (устройство, файл настройки, метка сокетов каждого). Состояние подбора
помощник пишет в файл состояния (`status` выхода — поле `plugin.state`), а о переписанном файле члена
говорит событием `revive`.

Что делает плагин:

1. **Регистрация.** На каждый туннель — своё устройство WARP. Ключ X25519 создаётся на роутере, в API
   Cloudflare уходит только открытая половина. Сразу после регистрации устройство включается вторым
   запросом. Если прямой API Cloudflare не отвечает, регистрация идёт через реле. Если не отвечают и реле,
   берётся готовая регистрация `santa-atmo.ru`: ключ в ней создан чужим сервером, а не на роутере,
   поэтому это последний запас.
   Регистрация хранится в `/etc/steer/warp/<группа>-<n>.reg` (права 0600). Новая
   делается только по необходимости: удалить устройство у Cloudflare нельзя.
2. **Подбор точек.** Кандидаты — адреса WARP из пулов 162.159.192/193/195, 188.114.96–99 и
   нескольких 8.x. Открытые порты (2408, 500, 1701, 4500, а если все закрыты — ещё 50 запасных) ищутся
   разом на адресах трёх разных пулов; найденное помнится 12 часов. Затем рукопожатие проверяется
   сразу со всеми кандидатами, по 16 за раз, и ответившие проверяются по одной:
   - потери и задержка — 10 эхо-запросов к 1.1.1.1 через туннель; точка, где ответы пошли и
     оборвались (так туннель рвёт DPI), отбрасывается;
   - HTTPS через туннель, колония Cloudflare, страна, которую видят сайты, и то, что WARP включён
     (`warp=on` в `cdn-cgi/trace`);
   - город и страна колонии (`speed.cloudflare.com/meta`).

   Подбор идёт на временных устройствах в отдельном пространстве сети плагина, поэтому туннели,
   которые сейчас несут трафик, он не трогает. Туннелям группы достаются по возможности разные колонии.
3. **Файл туннеля** `/etc/steer/warp/<группа>-<n>.conf` (формат awg-quick, 0600). Если в ядре есть
   AmneziaWG, в файле параметры обфускации и маска первого пакета I1. Без AmneziaWG пишется обычный
   WireGuard. Записав файл, плагин просит ядро перенастроить туннель.
4. **Сторож.** Раз в 30 секунд плагин проверяет каждый туннель: свежее рукопожатие или HTTPS через
   него. Первая же неудачная проверка — плагин говорит ядру, что туннель мёртв, и группа уходит с
   него в этом же проходе сторожа ядра, не дожидаясь, пока устареет рукопожатие. Две проверки подряд
   без ответа — плагин подбирает туннелю другую точку; снятый адрес полчаса не берётся снова. Если две
   замены подряд не помогли, третьей вместо новой точки плагин регистрирует новые ключи (не чаще раза
   в сутки на туннель). Если при
   подборе все точки рвёт DPI, плагин берёт следующую маску I1 (по кругу: QUIC, QUIC-2, DNS, STUN,
   iCloud-DNS, SIP) и подбирает снова; маска запоминается, и с ней пишутся следующие файлы туннелей.

5. **Самая быстрая точка.** Раз в `interval` (600 с) плагин меряет кандидатов и, если точка быстрее
   текущей больше чем на `tolerance` (50 мс) и не хуже по потерям, переставляет её у того же
   устройства — без нового интерфейса. Кандидаты и текущая точка меряются одинаково (эхо-запросы и
   HTTPS через туннель) на временных устройствах в пространстве сети плагина, отдельной регистрацией
   замера `/etc/steer/warp/<группа>-scan.reg`: ключ живого туннеля на втором устройстве увёл бы у
   него сессию. После смены туннель сразу делает рукопожатие с новой точкой. У новой точки бывает
   другая колония, а у колонии другой адрес выхода, поэтому долгие соединения через туннель при смене
   обрываются, а новые идут уже через быструю точку. Туннель, который сейчас не работает, сюда не
   попадает: ему точку меняет сторож.

Смена туннеля по задержке соединений не рвёт: у группы соединение закреплено за туннелем, на котором
началось, и новое идёт на выбранный (как у любой группы `order`/`latency`, [spec-v2.md](spec-v2.md)).
Умер туннель — его соединения обрываются (у другого туннеля другой адрес выхода, сервер их не узнает),
и приложения переподключаются через живой.

## MASQUE (`transport: masque`)

Вместо WireGuard — MASQUE, как в нынешнем официальном клиенте Cloudflare. Это QUIC с HTTP/3: IP-пакеты
идут датаграммами QUIC внутри запроса CONNECT-IP. Для провайдера это выглядит как обычный HTTP/3 на
443-м порту.

- Регистрация та же. Затем плагин включает у неё MASQUE: создаёт на роутере ключ P-256 и отдаёт в API
  его открытую половину. Ключ хранится в том же файле регистрации.
- Туннель члена — устройство TUN, которое держит плагин. Клиентский сертификат плагин выпускает сам,
  ключом регистрации. Ключ сервера сверяется с тем, что API выдал при включении.
- Точку входа выбирает Cloudflare: адрес эникаст, колония — ближайшая по сети. Поэтому плагин подбирает
  не адрес, а открытый порт. API называет 443, 500, 1701, 4500, 4443, 8443 и 8095. Плагин пробует все
  разом (рукопожатие, CONNECT и эхо-запрос через туннель) и раздаёт членам разные пары адрес:порт.
- По той же причине `countries` и `exclude_countries` у MASQUE колонию не выбирают. Страна видна в
  `status`, но сменить её подбором нельзя.
- Сторож, быстрый отказ и замена точки — те же, что у AmneziaWG. Масок I1 у MASQUE нет.
- Самая быстрая точка у MASQUE — пара адрес:порт: раз в `interval` плагин пробует все пары разом и
  переводит туннель на пару быстрее текущей больше чем на `tolerance`. Устройство TUN остаётся тем же,
  заново устанавливается только соединение QUIC под ним.

Команда `steer warp-scan` у группы MASQUE печатает пробы всех пар адрес:порт (`ok`, `rtt` или `error`).

## Ключи

| Ключ | Значение | Умолчание |
|---|---|---|
| `count` | сколько туннелей в группе, 1..255. Больше одного — запасные туннели: при отказе группа переключается сразу, без подбора, и колонии разные | 1 |
| `transport` | `awg` — AmneziaWG/WireGuard; `masque` — MASQUE (выше) | `awg` |
| `countries` | только эти страны, коды из двух букв (`[NL, DE]`) | любые |
| `exclude_countries` | кроме этих стран | никаких |
| `pick` | `latency` или `order` — как у группы | `latency` |
| `tolerance`, `interval` | только при `pick: latency`, как у группы; они же — допуск и период замера самой быстрой точки | 50 мс (как у группы), 600 с |
| `url`, `idle_timeout` | только при `pick: latency`, как у группы | как у группы |
| `on_fail` | как у группы | `drop` |
| `over` | туннели WARP идут через этот выход | напрямую |
| `ipv6` | `nat` — IPv6 клиентов идёт через WARP с подменой адреса (у регистрации WARP один адрес IPv6), `off` — без IPv6 | `nat` |

Страна точки — та, которую видят сайты. Исключение срабатывает и по стране колонии: выход через
российскую колонию заблокированное не открывает, даже если адрес числится зарубежным. По умолчанию
страны любые, в том числе Россия; чтобы её не брать — `exclude_countries: [RU]`. Одна страна в
`countries` и `exclude_countries` сразу — отказ.

Имя выхода `kind: warp` — не длиннее 27 знаков (у туннелей к нему добавляется «.<n>»), ключа `device`
у него нет: имена устройств туннелей выбирает ядро steer.

## Команды

- `steer warp-scan <группа>` — тот же подбор без замены туннелей; печатает JSON с точками: адрес,
  порт, класс (0 — годна, 1 — колония уже занята, 2 — HTTPS не проходит), потери, задержка, колония,
  страны.
- `steer warp-reg <файл>` — зарегистрировать устройство и сохранить регистрацию в файл. Если файл уже
  есть, используется он, и новая регистрация не создаётся.

## Что нужно на роутере

Плагин `warpbox` ставится из семени пакета ядра (`steer plugin install warpbox`) и тянет за собой
плагины `net1` и `awg`. Плагин `awg` ставит модуль ядра Linux для WireGuard: `kmod-amneziawg` (с
обфускацией), а если его нет в фидах — `kmod-wireguard`; отказ называет все пакеты, которые менеджер
пробовал. `kmod-tun`, нужный `transport: masque`, приходит с пакетом `steer-core`.

Подмену адреса (masquerade IPv4 и IPv6) для туннелей WARP ставит само ядро steer, в своей таблице. Зона
фаервола устройствам туннелей (`cf.1`, `cf.2`, …) всё равно нужна: fw4 пропускает транзит только между
зонами, и в устройство без зоны трафик клиентов не пройдёт. splify2 кладёт устройства в свою зону сам.
Устройства членов перечисляют `steer outputs --kind awg --devices` и `steer outputs --kind
plugin-device --devices`.
