# Cloudflare WARP (steer-warpbox)

Модуль `steer-warpbox` — выход через Cloudflare WARP одной строкой спеки. Он регистрирует устройства
WARP, подбирает рабочие точки входа, следит за ними и меняет ту, что перестала отвечать. Модуль есть
только в пакете `steer-warpbox`; в мета-пакет `steer-extended` он не входит.

```yaml
outputs:
  cf: { kind: warp }
rules:
  - { to: [blocked], out: cf }
```

## Как устроено

`kind: warp` — это группа (`pick: latency`) из `count` туннелей `cf.1`, `cf.2`, … вида `awg`. Устройства,
метки, таблицы, здоровье и выбор живого члена у них те же, что у любого выхода `awg` и любой группы
ядра steer: модуль не заводит ни интерфейсов netifd, ни зон и правил фаервола. Модуль — помощник группы:
ядро поднимает его само, когда в спеке есть `kind: warp`.

Что делает модуль:

1. **Регистрация.** На каждый туннель — своё устройство WARP. Ключ X25519 создаётся на роутере, в API
   Cloudflare уходит только открытая половина. Сразу после регистрации устройство включается вторым
   запросом. Если API Cloudflare не отвечает, регистрация идёт через запасной адрес.
   Регистрация хранится в `/etc/steer/warp/<группа>-<n>.reg` (права 0600). Новая
   делается только по необходимости: удалить устройство у Cloudflare нельзя.
2. **Подбор точек.** Кандидаты — адреса WARP из пулов 162.159.192/193/195, 188.114.96–99 и
   нескольких 8.x. Открытые порты (2408, 500, 1701, 4500, а если все закрыты — ещё 50 запасных) ищутся
   разом на адресах трёх разных пулов; найденное помнится 12 часов. Затем рукопожатие проверяется
   сразу со всеми кандидатами, по 16 за раз, и ответившие проверяются по одной:
   - потери и задержка — 10 эхо-запросов к 1.1.1.1 через туннель; точка, где ответы пошли и
     оборвались (так туннель рвёт DPI), отбрасывается;
   - HTTPS через туннель, колония Cloudflare, страна, которую видят сайты, и то, что WARP включён
     (`warp=on` в `cdn-cgi/trace`);
   - город и страна колонии (`speed.cloudflare.com/meta`).

   Подбор идёт на временных устройствах в отдельном пространстве сети модуля, поэтому туннели,
   которые сейчас несут трафик, он не трогает. Туннелям группы достаются по возможности разные колонии.
3. **Файл туннеля** `/etc/steer/warp/<группа>-<n>.conf` (формат awg-quick, 0600). Если в ядре есть
   AmneziaWG, в файле параметры обфускации и маска первого пакета I1. Без AmneziaWG пишется обычный
   WireGuard. Записав файл, модуль просит ядро перенастроить туннель.
4. **Сторож.** Раз в минуту модуль проверяет каждый туннель: свежее рукопожатие или HTTPS через него.
   Две проверки подряд без ответа — модуль подбирает туннелю другую точку. Если три замены подряд не
   помогли, модуль регистрирует новые ключи (не чаще раза в сутки на туннель). Если при подборе все
   точки рвёт DPI, модуль берёт следующую маску I1 (по кругу: QUIC, QUIC-2, DNS, STUN, iCloud-DNS,
   SIP) и подбирает снова; маска запоминается, и с ней пишутся следующие файлы туннелей.

## Ключи

| Ключ | Значение | Умолчание |
|---|---|---|
| `count` | сколько туннелей в группе, 1..255 | 3 |
| `transport` | `awg` (`masque` — следующий этап) | `awg` |
| `countries` | только эти страны, коды из двух букв (`[NL, DE]`) | любые |
| `exclude_countries` | кроме этих стран | `[RU]`, если не заданы ни `countries`, ни `exclude_countries` |
| `pick` | `latency` или `order` — как у группы | `latency` |
| `tolerance`, `interval` | как у группы с `pick: latency` | 50 мс (как у группы), 600 с |
| `url`, `idle_timeout`, `on_fail` | как у группы | как у группы |
| `over` | туннели WARP идут через этот выход | напрямую |
| `ipv6` | `nat` — IPv6 клиентов идёт через WARP с подменой адреса (у регистрации WARP один адрес IPv6), `off` — без IPv6 | `nat` |

Страна точки — та, которую видят сайты. Исключение срабатывает и по стране колонии: выход через
российскую колонию заблокированное не открывает, даже если адрес числится зарубежным. Российская
колония доступна явно: `countries: [RU]`.

## Команды

- `steer warp-scan <группа>` — тот же подбор без замены туннелей; печатает JSON с точками: адрес,
  порт, класс (0 — годна, 1 — колония уже занята, 2 — HTTPS не проходит), потери, задержка, колония,
  страны.
- `steer warp-reg <файл>` — зарегистрировать устройство и сохранить регистрацию в файл. Если файл уже
  есть, используется он, и новая регистрация не создаётся.

## Что нужно на роутере

Модуль ядра WireGuard: `kmod-amneziawg` (с обфускацией, сторонний) или `kmod-wireguard` из фидов
OpenWrt. В зависимостях пакета его нет — что ставить, решает человек. Туннели `cf.N` — обычные
устройства выхода: как и любому выходу `awg`, им нужна зона фаервола с masquerade (splify2 кладёт их
в свою зону сам).
