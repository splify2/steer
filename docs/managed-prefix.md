# Отдельный файловый префикс на Linux

`steerd --managed-prefix P plugin …` использует штатный менеджер из `steer-core`,
но работает только внутри **новой** приватной установки. Без этого аргумента
остаётся обычная раскладка 2.x. Для файлового префикса root и демон не нужны.

```sh
install -d -m 700 "$HOME/steer-local"
P="$HOME/steer-local/managed"
steerd --managed-prefix "$P" plugin init
# Проверенный открытый ключ издателя, роль plugins:
install -m 600 /путь/издатель.pub "$P/keys/plugins/издатель.pub"
steerd --managed-prefix "$P" plugin install --file /путь/к/steer-ui.s2p
steerd --managed-prefix "$P" plugin list --json
steerd --managed-prefix "$P" plugin status steer-ui --json
steerd --managed-prefix "$P" plugin remove steer-ui
```

Родитель `P` должен быть каноническим абсолютным каталогом владельца (0700)
вне рабочих путей других установок. Самого `P` до `init` быть не должно:
даже пустой каталог не принимается. В соседнем временном каталоге менеджер
создаёт всю раскладку, синхронизирует файлы и каталоги, публикует её одним
`renameat2(RENAME_NOREPLACE)` и синхронизирует родителя. После аварии до
публикации может остаться `.steer-init-*`; менеджер не принимает его за `P`
и не чистит чужие временные каталоги. Требуются поддержка этих операций ФС
и `statx(STATX_MNT_ID)` (Linux 5.8+) для проверки точек монтирования.

| Внутри `P` | Назначение |
|---|---|
| `installed`, `.stage` и `.prev` внутри него | Файлы, подготовка и откат установки. `installed/.lock` — **каталог**, обычная блокировка находится в `.lock/writer`. |
| `etc/repos.d`, `etc/sources.d` | Первое — **файл** с версией формата; определения источников находятся во втором. Старый `search` не читает новые источники и не начинает обновлять кэш. |
| `etc/state.json`, `etc/registry.json` | Первое — постоянный валидный пустой реестр для загрузчика 2.x; второе — рабочий реестр (0600). Отсутствующий `state.json` пустой реестр не заменяет. |
| `keys`, `seed`, `run`, `tmp`, `keep`, `sysroot` | Свои ключи, семя, рабочие и временные файлы, список сохранения и корень ссылок. Зарезервированы `run/ctl` (должен отсутствовать) и отдельный `run/state`. |

Выбор делается **до** поиска команд плагинов, обращения к сокету и обработки
тела ctl-запроса. Только `steerd` и перечисленные выше действия поддерживают
этот аргумент. `steer`, `steer-tools`, запуск демона, загрузчик команд и
ctl-сервер отвечают отказом. Переменные `STEER_*`, отдельные параметры путей
и посторонний `TMPDIR` с выбором префикса не совмещаются. Без opt-in старые
переопределения 2.x продолжают действовать.

Установка принимает один подписанный `.s2p` с метаданными `schema`, `id`,
`version`, `name`, `description`, `license`, `arch`, `compat`. Службы, хуки,
системные зависимости и расширения не допускаются; файлы UI устанавливаются,
но не запускаются. Группы, сетевые обновления, импорт из семени и `--unsigned`
не поддерживаются. Ограничение проверяется на подписанном манифесте **до**
переноса в `installed/ID`; при замене, снятии и replay проверяется и прежний
манифест. Незавершённую одиночную установку обнаруживают также `list/status`:
под блокировкой они восстанавливают файлы и снимок `registry.json` из журнала
`M1`. Повреждение обязательного пути, метки или старого пустого вида прерывает
команду до replay. Неизвестный журнал остаётся для разбора.

Владение относится ко **всему** набору путей. Не направляйте старый ctl,
внешний установщик или отдельные переменные 2.x в части `P`. Раскладка
отделяет штатных писателей, но не изолирует программы одного UID. Это не
история ID и не управление живыми службами. Для полного отката остановите
писателей и владельцев служб и переключите все пути на прежнюю остановленную
установку; копирование `state.json` и смешанная запись не являются откатом.

Для E4 существует отдельный [лабораторный тип поколения службы](../experimental/service-generation/README.md).
Он создаётся своим явным opt-in, не из `plugin.json` и не внутри файлового
префикса. Его квитанция проверяет запрет нового запуска конкретного поколения;
команды установки и снятия служб в `steerd --managed-prefix` не добавлены.

## Повторить проверку

На Linux x86_64 нужны права на создание частных mount/PID/network namespaces.
`LIBS_DIR` — выход штатного `build/build-libs.sh` (`steerd` и его `.so.*`);
`CLIENT` — тонкий клиент; `V214` и `PINNED` — неизменённые менеджеры `v2.1.4`
и `f00045d`. `UI` и `PUB` — подписанный архив из `steer-ui@900b76c` и его
открытый ключ. `S2P` используется только для подписания тестовой службы.

```sh
cc -shared -fPIC tests/managed-prefix-cut.c -ldl -o "$OUT/cut.so"
python3 tests/managed-prefix.py "$LIBS_DIR" "$CLIENT" "$V214" "$PINNED" \
    "$UI" "$PUB" "$S2P" "$OUT/cut.so"
```

Установки и чтения выполняет `nobody` с отключённым loopback. Тестовый
`LD_PRELOAD` применяется только к двум установкам для SIGKILL непосредственно
перед очисткой настоящего журнала. Остальные вызовы, включая восстановление,
исполняют штатный бинарник без перехвата.
