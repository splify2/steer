# Подготовка 2.2.0

База ветки `release/2.2.0` — тег `v2.1.4` (`70d11ebb`).
Исправления переносятся выборочно из
`3dbc2bf` ветки разработки 3.0.0; новая архитектура runtime/spec не переносится.

## Исправления и исходные сообщения

| Область | Изменение и проверка |
| --- | --- |
| helpers | Монотонные миллисекунды переведены с `long` на `int64_t`. Переполнение после 24,9 суток подтверждено; стенд проверен и настоящим 32-битным бинарником musl. Таймеры не вытесняют обработку событий. |
| Vision | DIRECT включается после полного кадра, включая padding. Регрессия воспроизводится на старом коде, исправленный тест проходит. |
| DNS | Новые таблица и правила принимаются одной операцией; ошибка загрузки сохраняет предыдущий рабочий снимок. Проверены повреждённые и оборванные обновления. |
| TLS / gRPC / XHTTP | Проверка порядка сообщений и CertificateVerify, KeyUpdate, ограниченная обработка post-handshake и заголовков HTTP/2. Размеры и смещения старых структур проверяются против v2.1.4. |
| Hysteria2 / QUIC | Потоковый разбор ответа, общий предел сборки UDP, освобождение по TTL, отказ отдельного устаревшего потока, резерв CID в размере датаграмм. Есть реальные QUIC, AEAD и sanitizer-стенды. |
| ARM | [#34](https://github.com/splify2/steer/issues/34): добавлена arm_cortex-a7. [#35](https://github.com/splify2/steer/issues/35): soft-float ARM собирается с явным запретом FP/NEON. Обе сборки проверены кросс-компилятором; запуск на физических роутерах ещё нужен. |

В splify2 26.11.6 исправляются сообщения об ошибках LuCI, удаление ранее созданных
списков с кириллицей, отображение ошибок индекса плагинов и ложный вывод о пустой
подписке, когда ядро посчитало только VLESS, а в подписке есть другие протоколы.
Соответствующее отображение ошибок индекса перенесено в Andromeda 26.11.2.

## Связь с сообщениями пользователей

| Сообщение | Найденная причина / граница исправления |
| --- | --- |
| Пустое красное уведомление | LuCI получал DOM-узел в позиции атрибутов `E`. Исправлено создание контейнера; проверка выполняет настоящий обработчик ошибки. |
| Список с кириллицей не удаляется | Проверка удаления требовала ASCII-имя, хотя старый файл уже существует. Для удаления допускается безопасное имя файла, включая кириллицу. Создание новых имён сохраняет прежний контракт. |
| Пустой каталог плагинов после перезагрузки | Интерфейс скрывал ошибки индекса; ядро могло потерять рабочий реестр при отказе обновления. Исправлены эти подтверждённые дефекты. Сбой DNS/зеркала без диагностики не объявляется устранённым. |
| HTTP-подписка работает, но сообщает об отсутствии узлов | Счётчик VLESS ошибочно трактовался как счётчик всех протоколов. При других протоколах нулевой VLESS-count больше не выдаётся за доказанно пустую подписку. |
| Нужна группа из нескольких разных протоколов | В текущей Andromeda соответствующая проверка уже исправлена; дублирующий перенос не выполнялся. |
| Проблемы gRPC и IPv6 узла | В базе уже есть прежние исправления gRPC и IPv6. Дополнительно проверены реальные gRPC/Xray, фрагментированный ответ VLESS и узел с AAAA. |
| Большой расход RAM на доменные списки, WARP latency, bootstrap DNS, аппаратный offload | Надёжной общей причины и готового исправления для каждого сообщения не установлено. Сжатие списков не добавлено. |

## REALITY и Xray 26.11.9

Сходные сообщения есть в [Steer #29](https://github.com/splify2/steer/issues/29)
и [splify2 #43](https://github.com/splify2/splify2/issues/43).
В апстриме обсуждались требования новых серверов к ClientHello и гибридному обмену:
[Xray #7259](https://github.com/XTLS/Xray-core/issues/7259),
[Mihomo #3476](https://github.com/MetaCubeX/mihomo/issues/3476).
Это возможная связь, а не установленная причина конкретного сообщения о Remnawave 3.4.6.

Локальный стенд использует собственную TLS-маскировку и одноразовые ключи, без чужих
подписок и серверов. С точным тегом Xray `v26.11.9` (`676eaf66`) кандидат успешно
выполняет REALITY-рукопожатие и передаёт данные. Тот же probe на исходниках `v2.1.4`
возвращает ошибку чтения после открытия транспорта, в том числе без переноса объекта
соединения в памяти. Конкретное сообщение «не может пройти проверку подлинности» и
конфигурация Remnawave не воспроизведены. Такой случай не объявляется закрытым.
Также проверен Xray main `4d0bfb4d` (три режима XHTTP поверх TLS и REALITY/TCP),
Hysteria main `7040c167` — прямое соединение, TCP/UDP, обфускация и восстановление.
На точном теге Xray `v26.11.9` отдельно прошёл VLESS/gRPC поверх TLS.

## Повторение проверок

Основные входы: `make test`, `make ext-test`, `make protocol-test`.
Для расширенного прогона нужны исходники зависимостей из рецептов `build/wolfssl`
и `build/ngtcp2`; задаются `STEER_WOLFSSL`, `STEER_NGTCP2`, `XRAY`, `HY2_SERVER`
и `PLUGIN_SDK`; для стенда менеджера также `S2P`. Отсутствующие внешние стенды печатают пропуск, который не равен проверке.

```sh
make protocol-test WOLFSSL_LIBRARY=/path/libwolfssl.a NGTCP2_LIBRARY=/path/libngtcp2.a
python3 tests/transportprobe_build.py --wolfssl-library /path/libwolfssl.a --output /tmp/transportprobe --sanitize
python3 tests/transport_interop.py --probe /tmp/transportprobe --xray /path/xray --network tcp --reality
python3 tests/transport_interop.py --probe /tmp/transportprobe --xray /path/xray
LIBS=build/libs-host HY2_SERVER=/path/hysteria sh tests/run-hy2.sh
```

Архивы wolfSSL/ngtcp2 должны сопровождаться `.cflags` своего рецепта сборки.
В Andromeda под Node 26 тесты запускаются с `NODE_OPTIONS=--no-experimental-webstorage`:
это отключает экспериментальный глобальный localStorage Node, мешающий jsdom.

Сжатие доменных списков в RAM, WARP latency и аппаратный offload из сообщений
пока не имеют подтверждённого исправления в этой ветке. Новые протоколы и возможности
3.0.0 в этот перенос не входят.

Отдельные проверки: модель плагинов — 96, менеджер плагинов — 219, восстановление
одиночной установки — 44 сценария, swapmatch — 77, netrestart — 78, Hysteria2 — 68.
Проверены сохранённый транспорт и поздний DNS-ответ после смены upstream, отказ
подготовки таблицы, повтор, обратная совместимость трубы и adoption резолвера.
Обе полные сборки ARM A7/A9 собраны с net1 и плагинами; в 12 ELF-файлах каждой
проверены интерпретатор soft-float musl и отсутствие FP/SIMD-инструкций.

Изменение `06f3f7f` касается `QC_WITH_ENDPOINT` нового управляемого QUIC-сервера,
которого в базе 2.1.4 нет. Новая архитектура runtime/spec/provider, Full managed UI,
Linux-префиксы, серверные endpoint и групповые файловые транзакции остаются в 3.0.0.
Изменения выбора HWID/TID и новые гарантии остановки служб не объявляются частью
этого переноса. Это выбранный набор исправлений стабильной линии, а не весь diff 3.0.0.

Полный прогон splify2 завершён без ошибок; подготовлены локальные ipk/apk 26.11.6
с Andromeda 26.11.2. ARM A7 .s2p и семя созданы для проверки упаковки с тестовым
ключом; это не опубликованные релизные архивы.

Проверка завершена для выбранного набора переносов:

- Основной набор проверен поэтапно: общий прогон остановился только на устаревшем
  подсчёте сообщений srs-read (10 вместо 8). После исправления buildmatch прошёл
  322 проверки; оставшиеся команды того же рецепта Makefile выполнены отдельным
  продолжением с кодом 0, включая финальные группы (111 проверок). Это не запись
  об одном непрерывном успешном запуске `make test`.
- `make ext-test` завершился с кодом 0; в поднаборе раскладки библиотек прошли
  118 проверок. Пропущенный из-за старого пути rcvwnd обновлён и проверен отдельно:
  6 проверок, включая масштабирование TCP-окна и потерю пакетов.
- Внешний Xray v26.11.9 не поддерживает `ss none`, этот случай остаётся пропуском.
  Общий стенд менеджера запускался отдельно с S2P (219 проверок), поскольку во
  внешнем прогоне инструмент отсутствовал в стандартном PATH.
- `make protocol-test`, fault injection IPv4/IPv6/blackhole, реестр назначений,
  DNS receipts/retry/adoption и восстановление установки пройдены.
- Полный набор splify2 прошёл; интеграция его бэкенда с окончательным ядром
  перепроверена (15 проверок). Andromeda: 946 пройдено, 25 штатно пропущено.
- Пакетный сборщик Docker собран отдельным образом. В этой среде для загрузки
  зависимостей потребовался `--network=host`; исправление time64 проверено
  динамической компоновкой ARM-программы внутри полученного образа.

Физические роутеры и конкретная чужая конфигурация Remnawave не проверялись.
Релизные артефакты подписываются и публикуются через Actions; локальные тестовые архивы для публикации не используются.

Для пакетной сборки требуется образ с обновлённым `build/Dockerfile`. Уже существующий
образ `steer-builder:wolfssl` автоматически не пересобирается. Пример отдельного
локального образа без замены прежнего:

```sh
docker build -t steer-builder:steer-2-2-0-check build/
STEER_BUILDER_IMAGE=steer-builder:steer-2-2-0-check sh build.sh
```

Для упаковки архитектуры ARM A7 требуется версия plugin-sdk с коммитом `644867b`
(локальная ветка `release/2.2.0` SDK). Архивы для проверки упаковки подписываются
тестовым ключом; production-ключи хранятся в Actions, публикация выполняется релизными workflow.
