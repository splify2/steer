# Схема спеки v2 — `steer spec-schema`

`steer spec-schema [--json]` печатает полную машиночитаемую схему спеки v2: разделы, ключи, типы,
значения enum, умолчания, пределы чисел, обязательность, подсказки по-русски, ссылки на имена записей
и условия, при которых ключ имеет смысл. По схеме каркас (splify2) строит форму на каждый ключ, не
зная ключей заранее; сырой редактор остаётся рядом. Формат ключей — тот же, что у вида плагина
(`kinds/<вид>.schema.json`, документация плагинов), поэтому каркас рисует и ядро, и плагины одним
кодом. Справочник самих ключей и отказов — [spec-v2.md](spec-v2.md).

- без `--json` — таблица для человека: путь ключа, тип, значения, умолчание, подсказка; у выходов —
  блок на каждый вид;
- `--json` — схема JSON-объектом (одна на платформу и сборку: на телефоне у `on_fail` нет `zapret`,
  у вида, которого нет в сборке, нет ключей, а есть причина).

## Откуда берётся схема

Отдельного списка ключей у схемы нет. Её строят:

- **таблицы ключей** `src/model/v2keys.c` — те же, по которым разбор (`src/model/v2.c`) решает, что
  ключ известен («неизвестный ключ» — отказ), берёт пределы чисел (`minimum`, `maximum`) и называет,
  чей ключ вида чужой («ключ strategy есть только у kind: recheck»). Новый ключ вносится в таблицу — и
  разбор, и схема узнают его вместе;
- **реестр видов** (`kind_ops.caps` и `.keys`): какому виду какие общие ключи (`on_fail`, `ipv6`,
  `prefix`, `over`, `device`) и ключи вида принадлежат. Предикат `v2key_applies` — один на разбор и
  схему;
- **реестр плагинов** (`plugin_n`, `plugin_at`): виды установленных плагинов с их схемами ключей.

Значения (разбор enum, сочетания ключей, ссылки по именам) остаются в разборе и в `src/kinds/<вид>.c`.
Чтобы схема не разошлась с ними, её сверяет стенд `tests/specschemamatch.sh` (раздел «Проверка»).

## Формат

Схема — подмножество JSON Schema (draft 2020-12) того же вида, что описывает ключи вида плагина:
`type`, `enum`, `const`, `default`, `pattern`, `minimum`, `maximum`, `minItems`, `maxItems`, `items`,
`properties`, `required`, `additionalProperties`, `description`, расширения `x-secret` и `x-path`. Всё
остальное — расширения ядра с префиксом `x-`: читатель, который их не знает, видит обычную схему и
теряет только условия и ссылки.

Корень:

| Ключ | Что |
|---|---|
| `type`, `properties`, `required`, `additionalProperties` | корневое отображение спеки: разделы `version`, `lan`, `clients`, `lists`, `outputs`, `dns`, `rules` |
| `x-schema-version` | версия формата схемы (сейчас 1) |
| `x-steer-version` | версия ядра, отдавшего схему |
| `x-platform` | `router` или `phone`: платформа, для которой построена схема |
| `x-plugins` | плагины реестра: `id`, `version`, `enabled`, `why` (у выключенного — причина), `kinds` |

Узел ключа:

| Ключ | Что |
|---|---|
| `type` | `string`, `integer`, `boolean`, `array`, `object` или список `["string", "object"]` |
| `description` | подсказка человеку |
| `enum`, `const`, `default`, `pattern`, `minimum`, `maximum`, `minItems`, `maxItems` | как в JSON Schema; у `array` — `items` с теми же словами для элемента |
| `x-example` | годное значение (для подсказки и для стенда); у записи — годная запись |
| `x-secret` | значение не печатается в status, diag и журнале (в таблицах ядра таких ключей сегодня нет; слово — для плагинов) |
| `x-path` | `etc`: строка — путь файла, относительный путь берётся от каталога файла спеки |
| `x-ref` | `{"section": "outputs", "also": ["direct"]}` — значение называет запись раздела (`outputs`, `lists`, `clients`, `dns.upstreams`); `also` — слова, допустимые кроме имён (`all`, `lan`, `direct`). У массива стоит на `items` |
| `x-when` | `{"pick": ["latency"]}` — ключ имеет смысл при таком значении соседнего ключа той же записи |
| `x-when-set` | `["obfs"]` — ключ имеет смысл, когда записаны эти соседи (`over` у `interface` — только с `obfs`) |
| `x-needs` | `{"device": ["for"]}` — при этом значении без этих соседей разбор отказывает; ключ `"*"` — при любом значении (`by` у туннеля — только рядом с `active`) |
| `x-one-or-list` | у массива: годится и одно значение вместо списка (`to: youtube`) |
| `x-unsupported` | ключ разбирается и проверяется, но спека с ним отвергается «ещё не поддерживается в этой версии ядра steer» |
| `x-platform` | `phone`: ключ принимает только телефон (`uid`, `self`, `app`) |
| `x-plugin` | у ключа плагина: id плагина, чья схема его задала |

**Записи «имя → запись»** (`clients`, `lists`, `outputs`, `dns.upstreams`): `type: object`,
`additionalProperties` — схема записи, `x-name` — `{"pattern", "maxLength", "reserved"}` для имени
(`reserved` — занятые слова: клиент `lan`, список `all`). **Список записей** (`rules`) — `type: array`
и `items`.

**Записи с вариантами.** Выход устроен по виду, а ключи вида разные, поэтому у записи `outputs.<имя>`
в `properties` стоит только `kind`, а полные схемы лежат в `x-variants`, по одной на вид:

- `x-discriminator`: `{"key": "kind", "then": {"tunnel": "protocol"}}` — имя варианта равно значению
  `kind`, а у `tunnel` — `tunnel:<protocol>` (`tunnel:vless`, `tunnel:hysteria2`, …; как имя вида в
  манифесте плагина);
- вариант — обычная запись (`properties`, `required`, `additionalProperties: false`) с
  `x-spec` (`{"kind": "tunnel", "protocol": "vless"}`) и `x-example` (годная запись: обязательные
  ключи с примерами). В `properties` варианта стоят **все** ключи этого вида — общие и свои, и
  только они; ключа, которого вида не знает, в варианте нет;
- вариант вида, которого нет в сборке, — `x-absent` с причиной («kind vless требует пакет
  steer-vless») и без ключей: форму для него нельзя нарисовать, а разбор такую спеку отвергает;
- `x-protocols` у записи — перечень протоколов `tunnel` (встроенных и плагинных).

`dns.upstreams.<имя>` и `dns` правила (`rules[].dns`: имя или запись) — тоже с вариантами:
`x-discriminator`: `{"has": "servers", "yes": "group", "no": "server"}` — есть ключ `servers`, и это
группа серверов, иначе — сервер. `type` у `rules[].dns` — `["string", "object"]`: строка — имя
сервера из `dns.upstreams` (`x-ref`), запись — один из вариантов.

## Пример

Выдержка из `steer spec-schema --json` (роутер; сокращено):

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "x-schema-version": 1,
  "x-steer-version": "2.0.5",
  "x-platform": "router",
  "x-plugins": [
    { "id": "warpbox", "version": "1.0.0", "enabled": true, "kinds": ["warp"] }
  ],
  "type": "object",
  "properties": {
    "version": { "type": "integer", "enum": [2], "x-example": 2 },
    "rules": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["to", "out"],
        "properties": {
          "to": {
            "type": "array",
            "description": "Списки из lists; all — весь трафик.",
            "items": { "type": "string", "x-ref": { "section": "lists", "also": ["all"] } },
            "minItems": 1,
            "x-one-or-list": true,
            "x-example": ["work"]
          },
          "scope": {
            "type": "string",
            "enum": ["device", "global"],
            "default": "global",
            "x-needs": { "device": ["for"] }
          }
        },
        "additionalProperties": false
      }
    },
    "outputs": {
      "type": "object",
      "x-name": { "pattern": "^[A-Za-z0-9_.-]+$", "maxLength": 31 },
      "additionalProperties": {
        "type": "object",
        "required": ["kind"],
        "properties": { "kind": { "type": "string", "enum": ["direct", "interface", "tunnel", "group", "warp"] } },
        "x-discriminator": { "key": "kind", "then": { "tunnel": "protocol" } },
        "x-variants": {
          "group": {
            "type": "object",
            "x-spec": { "kind": "group" },
            "x-example": { "kind": "group", "members": ["wg0", "wg1"] },
            "required": ["kind", "members"],
            "properties": {
              "kind": { "type": "string", "const": "group" },
              "pick": { "type": "string", "enum": ["order", "latency", "manual", "balance"], "default": "order" },
              "members": {
                "type": "array",
                "items": { "type": "string", "x-ref": { "section": "outputs" } },
                "minItems": 1,
                "x-one-or-list": true
              },
              "tolerance": {
                "type": "integer", "minimum": 0, "maximum": 60000,
                "x-when": { "pick": ["latency"] }
              }
            },
            "additionalProperties": false
          }
        }
      }
    }
  }
}
```

## Как по схеме строится форма

1. Корень: раздел — по `properties`; ключ с `type: object` и `properties` — вложенная группа полей
   (`dns.cache_ttl`, `outputs.<имя>.obfs`).
2. Запись «имя → запись» — список записей с кнопкой «добавить»; имя проверяется по `x-name`, новая
   запись начинается с `x-example`.
3. У записи с `x-variants` первым выбирается вариант (`kind`, у `tunnel` ещё `protocol`), потом рисуются
   `properties` этого варианта. Вариант с `x-absent` показывается недоступным, причина — из него.
4. Поле — по `type`: строка с `enum` — выбор, `integer` с `minimum` и `maximum` — число с пределами,
   `boolean` — переключатель, `array` — перечень (одно значение законно: `x-one-or-list`). `x-ref` —
   выбор среди записей раздела (плюс слова из `also`), `x-path` — поле пути. `description` — подсказка.
5. `x-when`, `x-when-set` и `x-needs` показывают или скрывают поле (и подсказывают соседа); решает
   разбор, форма только не предлагает бессмысленного.
6. `x-platform: phone` на роутере не рисуется; `x-unsupported` — рисуется с пометкой, спека с таким
   ключом применяться не будет.
7. Ключ, которого в схеме нет, форма не рисует — он остаётся в сыром редакторе.

## Виды плагинов

Виды включённых плагинов из реестра вливаются в `outputs` как варианты рядом с видами ядра, имя
варианта — имя вида из манифеста (`warp`, `tunnel:vless`):

- общие ключи вида (`on_fail`, `over`, `device`, `ipv6`, `prefix`) — по его свойствам `caps` из
  манифеста, как у вида ядра; одноимённый ключ схемы плагина общему не мешает и не действует (разбор
  читает общие ключи раньше схемы плагина);
- остальные ключи — из схемы ключей вида (`kinds/<вид>.schema.json`) как есть, каждый с `x-plugin:
  <id>`; `required` схемы плагина дополняет `required` варианта;
- схема ключей вида понимает те же слова `x-…`, что эта схема: `x-ref` (имя обязано быть записью
  раздела спеки или словом из `also`; проверка идёт, когда спека разобрана целиком, отказ называет ключ
  и имя), `x-one-or-list` (одно значение вместо списка), `x-needs` (значение без соседей — отказ) и
  подсказки форме `x-when`, `x-when-set`, `x-example` (разбор их не применяет). Они попадают в
  `spec-schema` как написаны; `x-plugin` ставит само ядро. `x-ref` с разделом вне `outputs`, `lists`, `clients`,
  `dns.upstreams` и слово не из списка схема вида отвергает;
- у ключа плагина без `x-example` пример берётся из `default`, первого значения `enum` или по типу
  и границам — чтобы `x-example` варианта был годной записью;
- у варианта `x-plugin: {"id", "version"}`;
- вид плагина, чьё имя совпало с видом ядра (`impl: core`: плагин даёт допуск, а код остаётся в ядре),
  замещает его вариант на его месте. Пока плагина `warp` нет, `kind: warp` разворачивает само ядро, и
  вариант `warp` строится из таблицы ключей (`V2S_WARP`);
- выключенный плагин и его виды в `x-variants` не попадают; он назван в `x-plugins` с `enabled: false`
  и причиной в `why`.

## Что в схему не входит

- `owner` у клиента, списка, правила и выхода: его пишет только плагин в подготовленной спеке
  (`spec.prepared.json`), в спеке человека разбор отвечает «owner пишет только плагин»;
- `kind: zapret` (убран из ядра, разбор называет замену), `kind: plugin-device` (его заводит только
  плагин-владелец) и недоступные виды без плагинной раскладки;
- ключ `strategy` (бит `KK_OPTS`, «только у kind: recheck»): ни один вид ядра его не принимает, модуль
  recheck подключается плагином со своей схемой ключей.

## Проверка

`tests/specschemamatch.sh` (входит в `make test`) строит из схемы тестовые спеки и прогоняет их через
настоящий разбор (`steerd spec convert`):

- каждый ключ схемы разбор принимает: на каждый ключ каждой записи и каждого варианта — спека с
  `x-example` и условиями (`x-when`, `x-when-set`, `x-needs`);
- каждое значение `enum` принято, чужое — нет; границы `minimum` и `maximum` приняты, за ними — отказ;
  одно значение вместо списка принято; ссылка на несуществующее имя — отказ; слова из `x-ref.also`
  приняты; пустой список при `minItems` отвергнут, `maxItems` принят и превышен;
- без обязательного ключа разбор отказывает; неизвестный ключ и ключ чужого вида — отказ;
- обратное: перечень «(есть: …)» из отказа разбора совпадает с ключами записи в схеме, а слова из
  таблиц справочника [spec-v2.md](spec-v2.md), которых нет в схеме, разбор не принимает;
- платформы: роутер, телефон (`STEER_PLATFORM=android`: `uid`, `self` и `app` принимаются, на роутере —
  «только на телефоне»);
- плагины: виды и ключи плагинов вливаются с `x-plugin`, их ключи принимает разбор, выключенный плагин
  назван в `x-plugins`;
- виды расширенной части (`vless`, `hysteria2`, `trojan`, `shadowsocks`, `socks`, `http`, `vmess`,
  `xsteer`) — в сборке с модулями: `tests/libs-test.sh` (`make libs-test`, входит в `tests/ext-test.sh`)
  зовёт тот же стенд на раскладке с модулями; в `make test` таких видов нет, и схема называет их
  недоступными.
